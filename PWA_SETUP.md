# PWA Setup for CHART Dental

Your Next.js + Laravel project has been configured as a Progressive Web App (PWA). Here's what's been set up:

## ✅ What's Installed & Configured

### 1. **next-pwa Package**
   - Automatically installed
   - Handles service worker registration and caching strategies
   - Configured to disable in development for faster hot-reload

### 2. **PWA Manifest** (`public/manifest.json`)
   - Defines app metadata (name, icons, theme colors)
   - Specifies display mode as "standalone" (hides browser UI)
   - Includes app shortcuts for quick access to dashboard
   - Categories tagged for app stores (medical, productivity)

### 3. **Service Worker**
   - Auto-generated by next-pwa
   - Enables offline support with intelligent caching
   - Located at: `/service-worker.js` (generated at build time)

### 4. **Meta Tags & Icons** (`src/app/layout.tsx`)
   - Viewport configuration for responsive design
   - Apple Web App settings for iOS installation
   - Theme colors for browser UI
   - Apple touch icons for home screen

### 5. **PWA Install Prompt** (`src/components/PwaInstallPrompt.tsx`)
   - Shows install prompt to eligible users
   - Only appears on installable browsers (Chrome, Edge, etc.)
   - Users can install from "Install" button or browser menu

## 📱 Next Steps

### 1. **Add App Icons** (REQUIRED)
   Create PNG icons in `public/icons/`:
   - `icon-192x192.png` - Standard icon
   - `icon-512x512.png` - High-res icon
   - `icon-192x192-maskable.png` - For adaptive icons (Android)
   - `icon-512x512-maskable.png` - For adaptive icons (Android)

   See `public/icons/README.md` for detailed requirements.

   Quick generation with ImageMagick:
   ```bash
   convert logo.png -resize 192x192 public/icons/icon-192x192.png
   ```

### 2. **Update Manifest Colors**
   In `public/manifest.json`:
   - Change `"theme_color"` to your brand color
   - Change `"background_color"` to your preference
   - Add your app name and description

### 3. **Update Layout Title**
   In `src/app/layout.tsx`:
   - Customize `title` and `applicationName` metadata
   - Update manifest link if needed

### 4. **Configure Offline Behavior** (Optional)
   In `next.config.ts`, you can customize caching:
   ```typescript
   export default withPWA({
     dest: 'public',
     register: true,
     skipWaiting: true,
     sw: 'service-worker.js', // custom SW file
     disable: process.env.NODE_ENV === 'development',
     runtimeCaching: [
       {
         urlPattern: /^https:\/\/api\/.*/i,
         handler: 'NetworkFirst',
         options: {
           cacheName: 'api-cache',
           expiration: {
             maxEntries: 200,
             maxAgeSeconds: 4 * 60 * 60, // 4 hours
           },
         },
       },
     ],
   })(nextConfig);
   ```

### 5. **Test PWA Features**
   ```bash
   npm run build
   npm start
   ```

   Then in Chrome DevTools:
   - Go to **Application** → **Manifest**
   - Check if manifest loads correctly
   - Go to **Application** → **Service Workers**
   - Verify service worker is registered
   - Test offline by clicking "Offline" checkbox

## 🔐 Security Notes

- PWA requires HTTPS in production (http://localhost works for dev)
- Service worker caches your API responses
- Update caching strategy if API responses are sensitive
- CSP headers already configured in `next.config.ts`

## 🐛 Troubleshooting

**App won't install:**
- Check if HTTPS is enabled (required for prod)
- Verify manifest.json is accessible at `/manifest.json`
- Check service worker registration in DevTools

**Service worker not updating:**
- Hard refresh (Ctrl+Shift+R)
- Clear cache in Application → Clear storage
- Service worker updates check on every page visit

**Offline doesn't work:**
- Verify service worker is registered
- Check if route is in runtimeCaching config
- NetworkFirst strategy tries network first, then cache
